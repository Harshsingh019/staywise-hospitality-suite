# Staywise

Staywise is a hotel booking and operations platform built with React, Express, and MongoDB. Guest reservations and hotel team workflows share rooms, bookings, payments, and service requests. The public Pages site runs as a self-contained browser demo; connecting the API enables shared data, authentication, and payment integrations.

## Demo

- Live demo: https://harshsingh019.github.io/staywise-hospitality-suite/
- Repository: https://github.com/Harshsingh019/staywise-hospitality-suite

Choose **Sign in → Explore a demo** to open the admin, hotel team, or guest experience. Demo bookings are saved in the current browser and do not collect payment.

## Features

- Guest room search, reservations, cancellation, invoices, reviews, email verification, and service requests
- Front desk arrivals, check-in/check-out, room inventory, housekeeping, and guest request assignment
- Multi-property administration, team roles, audit history, reports, and notifications
- React, React Router, Redux Toolkit, Axios, Bootstrap, Material UI, Recharts, and Socket.IO client
- Express API, MongoDB/Mongoose, JWT sessions, bcrypt password hashing, validation, SMTP email, Stripe payments, and image uploads
- GitHub Pages demo workflow, Docker Compose MongoDB, and a Render API blueprint

## Run locally

Requirements: Node.js 22.12 or newer and Docker (or a MongoDB 7 server).

~~~sh
cp .env.example .env
docker compose up -d mongo
npm install
npm run seed
npm run dev
~~~

Open the client at http://localhost:5173 and API health at http://localhost:5000/api/health.

The seed script creates a sample Paris property and development accounts:

| Role | Email |
| --- | --- |
| Administrator | admin@staywise.local |
| Hotel team | staff@staywise.local |
| Guest | guest@staywise.local |

All seeded accounts use the development-only password **Staywise!Demo2026**. Production seeding is disabled unless explicitly enabled; change the sample password before exposing seeded accounts.

## Configuration

Copy .env.example to .env. MONGODB_URI and a long random JWT_SECRET are required by the API. SMTP and Stripe settings are optional for local development. Without SMTP, verification and reset links are printed in the API terminal; without Stripe, local development exposes a no-charge test payment. These shortcuts are disabled in production.

CLIENT_URL is the client base URL for email and payment redirects. CLIENT_ORIGINS is the comma-separated list of allowed browser origins, without paths. The Pages values are:

~~~text
CLIENT_URL=https://harshsingh019.github.io/staywise-hospitality-suite/
CLIENT_ORIGINS=https://harshsingh019.github.io
~~~

Set VITE_API_URL at client build time to connect the React app to a deployed API. Keep secrets only in the API provider's environment settings; never add a .env file to Git.

## Deploy

### Public demo

The Deploy demo to GitHub Pages workflow builds the client whenever changes are pushed to main, then publishes client/dist. It uses a hash router and the repository subpath so direct demo links work on Pages.

### Full API

1. Create a MongoDB Atlas database and configure network access for the API host.
2. In Render, create a Blueprint from this repository using render.yaml.
3. Supply MONGODB_URI, CLIENT_URL, CLIENT_ORIGINS, SMTP settings, and Stripe secrets in the Render environment. JWT_SECRET is generated by the blueprint.
4. Configure a Stripe webhook at /api/payments/webhook for checkout.session.completed and checkout.session.async_payment_failed, and set STRIPE_WEBHOOK_SECRET.
5. Set the repository Actions variable VITE_API_URL to https://<your-render-service>/api to connect Pages to the API. Leave it unset for the self-contained demo.

A connected production deployment needs a MongoDB provider and the relevant email/payment credentials.

## API areas

All endpoints are under /api. Authenticated requests use Authorization: Bearer <token>.

| Area | Capabilities |
| --- | --- |
| Auth | Registration, email verification, login, current user, password reset |
| Rooms | Search, availability, occupancy, room management, image upload |
| Reservations | Search, list, create, detail, cancellation, invoice, check-in/out |
| Payments | Stripe Checkout/webhook, demo payment, refunds |
| Hotel team | Service requests, housekeeping, reservation operations |
| Admin | Dashboard, reports, users, properties, audit logs |
| Guest | Notifications and post-stay reviews |

Room booking updates the room calendar atomically to reject overlapping stays. Role checks are applied at route boundaries.
